# 자연어와 단어의 분산 표현

## 1. 자연어 처리

우리가 평소에 쓰는 말을 자연어라고 한다. 자연어 처리(NLP)를 문자 그대로 해석하면 자연어를 처리하는 분야이고, 우리의 말을 컴퓨터에게 이해시키기 위한 기술(분야)이다.

자연어 처리가 추구하는 목표는 사람의 말을 컴퓨터가 이해하도록 만들어서, 컴퓨터가 우리에게 도움이 되는 일을 수행하게 하는 것이다.

## 2. 단어

말은 문자로 구성되지만 문자 하나에는 의미가 없고, 의미는 단어 단위에서 생긴다. 즉 단어는 의미의 최소 단위이므로, 자연어 처리에서는 컴퓨터가 단어의 의미를 이해하도록 만드는 것이 출발점이다.

## 3. 시소러스

단어의 의미를 나타내는 방법으로는 먼저 사람이 직접 단어의 의미를 정의하는 방식을 생각할 수 있다. 단 일반적인 사전이 아니라 시소러스 형태의 사전을 애용했다.

시소러스란 유의어 사전으로, 뜻이 같은 단어(동의어)나 뜻이 비슷한 단어(유의어)가 한 그룹으로 분류되어 있다. 또한 자연어 처리에 이용되는 시소러스에서는 단어 사이의 상위와 하위, 혹은 전체와 부분 등 더 세세한 관계까지 정의해 둔 경우가 있다.

모든 단어에 대한 유의어 집합을 만든 다음 단어들의 관계를 그래프로 표현하면 단어 사이의 연결을 정의할 수 있다. 이 단어 네트워크를 이용하여 컴퓨터에게 단어 사이의 관계를 가르칠 수 있다. 이 정도면 컴퓨터에게 단어의 의미를 이해시켰다고 주장할 수 있고, 그 지식을 이용하면 우리에게 유용한 일들을 컴퓨터가 수행하도록 할 수 있다.

### WordNet

자연어 처리 분야에서 가장 유명한 시소러스는 WordNet이다. WordNet을 사용하면 유의어를 얻거나 단어 네트워크를 이용할 수 있고, 단어 네트워크를 사용해 단어 사이의 유사도를 구할 수도 있다.

### 시소러스의 문제점

WordNet과 같은 시소러스에는 수많은 단어에 대한 동의어와 계층 구조 등의 관계가 정의돼 있다. 하지만 이처럼 사람이 수작업으로 레이블링하는 방식에는 결점이 존재한다. 첫째, 시대 변화에 대응하기 어렵다. 둘째, 사람을 쓰는 비용이 크다. 셋째, 단어의 미묘한 차이를 표현할 수 없다.

이 문제를 피하기 위해 통계 기반 기법과 신경망을 사용한 추론 기반 기법이 쓰인다. 이 두 기법에서는 대량의 텍스트 데이터로부터 단어의 의미를 자동으로 추출한다.

## 4. 말뭉치와 전처리

말뭉치(corpus)는 자연어 처리를 위해 모아 둔 대량의 텍스트 데이터다. 자연어 처리 연구나 앱을 염두에 두고 수집된 텍스트 데이터를 일반적으로 말뭉치라고 한다. 사람이 쓴 문장은 그대로는 컴퓨터가 계산할 수 없으므로, 정제 → 정규화 → 토큰화 → 정수 인코딩과 패딩 → 벡터화 과정을 거쳐 숫자(벡터)로 바꿔 모델에 넣는다.

### 정제

정제는 분석에 방해되는 불필요한 문자를 지우는 단계다. 특수문자, 이모티콘, 반복 문자(ㅋㅋㅋ), HTML 태그, URL 등을 지운다. 예를 들어 "이 노트북 진짜 좋아요ㅋㅋㅋ!!"는 "이 노트북 진짜 좋아요"가 된다. 의미 없는 기호가 단어로 취급되면 단어 수만 늘고 학습에 방해가 되기 때문이다.

### 정규화(텍스트)

정규화는 표현이 다르지만 같은 의미인 단어를 하나로 통일하고, 의미에 크게 기여하지 않는 단어를 제거하는 단계다. 불용어 제거는 "이", "을", "the", "a"처럼 자주 나오지만 의미 정보가 적은 단어를 빼는 것이다. 형태 통일은 "좋아요", "좋았다", "좋은"을 "좋다"처럼 기본형으로 맞추는 것이다(영어는 대소문자 통일, "running" → "run" 등). 예를 들어 "이 노트북 진짜 좋아요"는 "노트북 진짜 좋다"가 된다. 같은 의미가 여러 형태로 흩어지면 모델이 다른 단어로 인식해 학습이 비효율적이기 때문이다.

### 토큰화

토큰화는 문장을 모델이 처리할 최소 단위(토큰)로 나누는 단계다. 예를 들어 "노트북 진짜 좋다"는 ["노트북", "진짜", "좋", "다"]가 된다. 영어는 공백 기준으로도 어느 정도 나뉘지만, 한국어는 조사·어미가 붙어 있어 형태소 분석기로 나누는 경우가 많다. 의미의 단위가 단어(토큰)이므로, 의미 단위로 쪼개야 각 단어에 의미를 부여할 수 있다.

### 단어·형태소·문자 단위 토큰화

토큰을 어떤 단위로 나누느냐에 따라 토큰화 방식이 달라진다.

단어 단위는 공백 등을 기준으로 단어를 하나의 토큰으로 나누는 방식이다. 직관적이지만 "play", "plays", "playing"이 모두 다른 토큰이 되어 단어 사전이 커지고, 사전에 없는 처음 보는 단어(OOV, Out-Of-Vocabulary)는 <unk> 같은 하나의 토큰으로 처리할 수밖에 없다. 책에서는 모든 문자를 소문자로 바꾸고 마침표 앞에 공백을 넣은 뒤 공백 기준으로 나누는 단어 단위 토큰화만 사용한다.

형태소 단위는 의미를 가진 가장 작은 말의 단위인 형태소로 나누는 방식이다. 한국어는 "노트북이", "노트북을"처럼 단어에 조사·어미가 붙어 공백만으로는 의미 단위를 나누기 어렵다. 그래서 형태소 분석기(Okt, Mecab, Kiwi 등)를 사용해 "노트북 / 이"처럼 나눈다.

문자 단위는 글자 하나하나를 토큰으로 삼는 방식이다. 사전은 매우 작고 OOV 문제가 없지만, 문장이 아주 긴 토큰 시퀀스가 되고 토큰 하나가 의미를 거의 담지 못한다.

### 서브워드 토큰화와 BPE

서브워드 단위는 단어를 더 작은 조각으로 나누는 방식이다. 자주 쓰이는 단어는 하나의 토큰으로 두고, 드문 단어는 자주 나오는 조각들의 조합으로 표현한다. 예를 들어 "playing"을 "play"와 "ing"으로 나누는 식이다. 처음 보는 단어도 이미 아는 조각들로 표현할 수 있어 OOV 문제가 줄고, 단어 사전 크기도 적절히 유지할 수 있다. 현재 LLM에서 사용하는 표준 방식이다.

대표적인 서브워드 방식인 BPE(Byte Pair Encoding)는 모든 단어를 문자 단위로 쪼갠 뒤, 말뭉치에서 가장 자주 붙어 나오는 두 조각을 찾아 하나의 새 토큰으로 합치는 과정을 정해 둔 사전 크기가 될 때까지 반복해 단어 사전을 만든다. 예를 들어 "low", "lower", "lowest"가 자주 나오면 "l"과 "o"가 먼저 "lo"로 합쳐지고, 이어서 "lo"와 "w"가 "low"로 합쳐진다. 결과적으로 "low"는 하나의 토큰이 되고, "lowest"는 "low"와 "est"처럼 나뉜다. WordPiece, SentencePiece도 비슷한 원리의 서브워드 방식이다.

### LLM과 토큰 수

LLM에서는 토큰이 처리의 기본 단위이기 때문에, 입력할 수 있는 길이(컨텍스트 길이)와 사용 비용이 모두 토큰 수를 기준으로 계산된다. 같은 문장이라도 토큰화 방식과 언어에 따라 토큰 수가 달라지며, 일반적으로 한국어는 영어보다 같은 내용에 더 많은 토큰이 필요하다.

### 정수 인코딩과 패딩

정수 인코딩은 단어마다 고유한 번호(ID)를 붙인 단어 사전을 만들고, 토큰을 번호로 바꾸는 것이다(노트북 → 812, 진짜 → 45, 좋 → 233, 다 → 19). 패딩은 문장마다 길이가 다르므로 짧은 문장 뒤에 0을 채워 길이를 맞추는 것이다([812, 45, 233, 19, 0, 0]). 컴퓨터는 문자가 아닌 숫자만 계산할 수 있고, 배치 처리를 하려면 입력 크기가 같아야 하기 때문이다.

### 벡터화(임베딩)

벡터화는 각 단어 ID를 여러 개의 실수로 이루어진 벡터로 바꾸는 단계다([[0.12, −0.40, …], [0.88, 0.05, …], …] → 모델 입력). 단어 번호 812와 45는 크기 차이에 의미가 없다. 벡터로 표현하면 비슷한 의미의 단어끼리 가까운 위치에 놓여, 단어의 의미와 관계를 숫자로 담을 수 있다. 이 벡터를 학습으로 만드는 대표적인 방법이 책 뒤에서 배울 word2vec이다.

## 5. 통계 기반 기법

### 단어의 분산 표현

전처리 이후 우리가 원하는 것은 단어의 의미를 정확하게 파악할 수 있는 벡터 표현이다. 이를 자연어 처리 분야에서는 단어의 분산 표현이라고 한다. 단어의 분산 표현은 단어를 고정 길이의 밀집 벡터로 표현한다. 밀집 벡터는 대부분의 원소가 0이 아닌 실수인 벡터를 말한다.

### 분포 가설

단어를 벡터로 표현하는 연구는 모두 단 하나의 간단한 아이디어에 뿌리를 두고 있다. 바로 단어의 의미는 주변 단어에 의해 형성된다는 것이다. 이를 분포 가설이라고 한다. 단어 자체에는 의미가 없고 그 단어가 사용된 맥락이 의미를 형성한다는 것이다. 물론 의미가 같은 단어들은 같은 맥락에서 더 많이 등장한다.

맥락은 특정 단어의 주변에 놓인 단어들로, 윈도우 크기(중심 단어 좌우로 볼 단어 수) 안에 들어오는 단어를 말한다. 윈도우 크기가 1이면 좌우 한 단어씩이, 윈도우 크기가 2이면 좌우 두 단어씩이 맥락에 포함된다.

### 동시발생 행렬

분포 가설에 기초해 단어를 벡터로 나타내는 방법으로 주변 단어를 세어 보는 방법이 자연스럽게 떠오른다. 어떤 단어에 주목했을 때 그 주변에 어떤 단어가 몇 번이나 등장하는지를 세어 집계하는 방법이다.

예를 들어 "you say goodbye and i say hello ."라는 문장에서 윈도우 크기를 1로 하고 단어 ID가 0인 "you"부터 시작해 보자. you의 맥락은 say라는 단어 하나뿐이다. 이를 표로 정리하면 다음과 같다.

```text
       you  say  goodbye  and  i  hello  .
you     0    1      0      0   0    0    0
```

따라서 you라는 단어를 [0, 1, 0, 0, 0, 0, 0]이라는 벡터로 표현할 수 있다. 같은 방식으로 say는 [1, 0, 1, 0, 1, 1, 0]이다. 모든 단어에 대해 동시발생하는 단어를 표에 정리하면, 이 표의 각 행은 해당 단어를 표현한 벡터가 된다. 이 표가 행렬의 형태를 띤다는 뜻에서 동시발생 행렬이라고 한다.

### 벡터 간 유사도

단어 벡터의 유사도를 나타낼 때는 코사인 유사도를 자주 사용한다.

```text
similarity(x, y) = x·y / (‖x‖ ‖y‖)
                 = (x₁y₁ + … + xₙyₙ) / (√(x₁² + … + xₙ²) √(y₁² + … + yₙ²))
```

분자에는 벡터의 내적이, 분모에는 각 벡터의 노름이 등장한다. 노름은 벡터의 크기를 나타내며, 여기에서는 L2 노름을 계산한다. 핵심은 벡터를 정규화하고 내적을 구하는 것이다. 코사인 유사도 값은 −1에서 1 사이이며, 값이 클수록 유사성이 크다고 할 수 있다.

## 6. 통계 기반 기법 개선하기

### 상호정보량

동시발생 행렬에는 문제점이 있다. 고빈도 단어로 눈을 돌려 보면 그 이유를 알 수 있다. 단순히 등장 횟수만 본다면 car는 drive보다 the와의 관련성이 훨씬 강하다고 나올 것이다. the가 고빈도 단어이기 때문이다. 이 문제를 해결하기 위해 점별 상호정보량(PMI)이라는 척도를 사용한다. PMI는 확률 변수 x와 y에 대해 다음 식으로 정의한다.

```text
PMI(x, y) = log₂ P(x, y) / (P(x) P(y))
```

P(x)는 x가 일어날 확률, P(y)는 y가 일어날 확률, P(x, y)는 x와 y가 동시에 일어날 확률이다. 이 PMI 값이 높을수록 관련성이 높다는 의미다.

이 PMI에도 한 가지 문제가 있다. 두 단어의 동시발생 횟수가 0이면 log₂0 = −∞가 된다는 점이다. 이 문제를 피하기 위해 실제로 구현할 때는 양의 상호정보량(PPMI)을 사용한다.

```text
PPMI(x, y) = max(0, PMI(x, y))
```

PMI가 음수일 때는 0으로 취급하므로, 단어 사이의 관련성을 0 이상의 실수로 나타낼 수 있다.

### 차원 감소

PPMI 행렬에도 여전히 큰 문제가 있다. PPMI 행렬은 단어 수 × 단어 수 크기라서, 말뭉치의 어휘 수가 증가함에 따라 각 단어 벡터의 차원 수도 증가한다. 어휘가 10만 개면 단어 하나의 벡터 길이도 10만이다. 또한 대부분의 단어는 서로 함께 나오지 않으니 행렬의 원소 대부분이 0이다. 각 원소의 중요도가 낮다는 뜻이다. 이런 벡터는 너무 길어 계산이 무겁고, 정보가 흩어져 있으며, 노이즈에 약하고 견고하지 못하다. 이 문제에 대처하고자 자주 수행하는 기법이 바로 벡터의 차원 감소다.

차원 감소는 문자 그대로 벡터의 차원을 줄이는 방법을 말한다. 중요한 정보는 최대한 유지하면서 줄이는 게 핵심이다. 그래서 데이터의 분포를 고려해 중요한 축을 찾는 일을 수행한다.

그림: 2차원 좌표에 점들이 비스듬한 직선 모양으로 퍼져 있다. 점들이 퍼진 방향으로 새 축을 하나 그으면, 각 점을 (x, y) 두 값 대신 그 축 위의 위치 하나의 값으로 표현할 수 있다

점들이 그 축을 따라 넓게 퍼져 있으니, 1차원 값만으로도 데이터의 본질적인 차이를 구별할 수 있다. 즉 차원 감소는 데이터가 가장 넓게 퍼진 중요한 방향(축)을 찾아 그 축들로만 다시 표현하는 것이고, 덜 중요한 방향은 버려도 정보 손실이 적다.

원소 대부분이 0인 행렬 또는 벡터를 희소 행렬 또는 희소 벡터라 한다. 차원 감소의 핵심은 희소 벡터에서 중요한 축을 찾아내어 더 적은 차원으로 다시 표현하는 것이다. 차원 감소의 결과로 원래의 희소 벡터는 원소 대부분이 0이 아닌 값으로 구성된 밀집 벡터로 변환된다. 이 조밀한 벡터야말로 우리가 원하는 단어의 분산 표현이다.

### 특잇값분해(SVD)

차원 감소에는 특잇값분해(SVD)를 이용한다. SVD는 임의의 행렬 X(여기서는 PPMI 행렬)를 U, S, V라는 세 행렬의 곱으로 분해한다.

```text
X = U S Vᵀ
```

U와 V는 직교행렬이고, 열벡터는 서로 직교한다. 직교행렬 U는 어떠한 공간의 축을 형성하며, 우리의 맥락에서는 이 U 행렬을 "단어 공간"으로 취급할 수 있다. U의 각 행은 단어 하나를 새 축 기준으로 다시 쓴 것이다. V는 반대쪽(맥락 쪽) 축 정보다. S는 대각행렬로, 대각 성분에는 특잇값이 큰 순서로 나열되어 있다. 특잇값은 쉽게 말해 해당 축의 중요도라고 간주할 수 있다. 즉 S는 축의 중요도 순위표이고, 앞쪽 축일수록 데이터를 많이 설명하고 뒤쪽 축은 거의 영향이 없다. 그래서 중요도가 낮은 원소를 깎아 내는 방법을 생각할 수 있다.

행렬 S에서 특잇값이 작다면 중요도가 낮다는 뜻이므로, 행렬 U에서 여분의 열벡터를 깎아 내어 원래의 행렬을 근사할 수 있다. 순서로 보면, S에서 큰 특잇값 k개만 남기고(S′), 그에 대응하는 U의 앞쪽 k개 열만 남긴다(U′). 행렬 X의 각 행에는 해당 단어 ID의 단어 벡터가 저장되어 있으며, 그 단어 벡터가 행렬 U′라는 차원 감소된 벡터로 표현되는 것이다. U′의 각 행이 그 단어의 k차원 벡터가 된다.

그래서 원래 길이 10만짜리 단어 벡터가, 예를 들어 길이 100짜리 밀집 벡터로 바뀐다.

### Truncated SVD

행렬의 크기가 N이면 SVD 계산은 O(N³)이 걸린다. 계산량이 N의 3제곱에 비례해 늘어난다는 뜻이다. 그래서 더 빠른 기법인 Truncated SVD 같은 방법을 이용한다.

일반 SVD는 행렬을 U, S, V로 분해해 모든 특잇값을 구할 뿐 아무것도 버리지 않는다(X = USVᵀ). 특잇값이 큰 k개만 남기고 나머지를 버려 원래 행렬을 근사하는 것이 Truncated SVD이며, 처음부터 상위 k개만 계산해 큰 행렬에서도 빠르다.

## 7. PTB 데이터셋

펜 트리뱅크(PTB) 말뭉치는 너무 크지 않은 적당한 말뭉치로, 주어진 기법의 품질을 측정하는 벤치마크로 자주 이용된다. PTB는 텍스트 파일로 제공되며, 한 문장이 하나의 줄로 저장되어 있다. 드물게 나오는 단어를 <unk>, 숫자를 N, 문장 끝을 <eos>로 바꾸는 전처리가 이미 되어 있다.

## 8. BoW와 TF-IDF

BoW와 TF-IDF도 단어의 등장 횟수를 세는 통계 기반 방법이다. 다만 책의 통계 기반 기법이 단어를 벡터로 표현하는 반면, BoW와 TF-IDF는 문서(문장)를 벡터로 표현한다는 점이 다르다. 그래서 주로 문서 분류나 검색에 쓰인다.

### BoW

BoW(Bag of Words)는 문서 안에 각 단어가 몇 번 등장하는지 세어 문서를 벡터로 표현하는 방법이다. 단어들을 가방에 넣고 섞는 것처럼, 단어의 순서는 무시하고 등장 횟수만 본다.

예를 들어 문장 A "you say goodbye"와 문장 B "i say hello"가 있고, 단어 사전이 [you, say, goodbye, i, hello]라면 다음과 같이 표현된다.

```text
         you  say  goodbye  i  hello
문장 A    1    1      1     0    0
문장 B    0    1      0     1    1
```

동시발생 행렬은 "단어 주변에 어떤 단어가 나왔나"를 세고, BoW는 "문서 안에 어떤 단어가 나왔나"를 센다.

### TF-IDF

BoW는 "the", "a"처럼 모든 문서에 자주 나오는 단어도 큰 값을 가지는 문제가 있다. 동시발생 행렬에서 the 같은 고빈도 단어 때문에 관련성이 왜곡되던 것과 같은 문제다. TF-IDF는 여러 문서에 흔하게 나오는 단어의 가중치를 낮춰 이를 해결한다.

```text
TF-IDF(t, d) = TF(t, d) × IDF(t)
IDF(t) = log(N / df(t))
```

TF(t, d)는 문서 d에서 단어 t가 등장한 횟수, N은 전체 문서 수, df(t)는 단어 t가 등장한 문서 수다. 특정 문서에 자주 나오지만(TF가 큼) 다른 문서에는 잘 안 나오는(IDF가 큼) 단어일수록 그 문서를 잘 나타내는 단어로 보고 큰 값을 준다. 위 예시에서 say는 두 문장 모두에 나오므로 IDF = log(2/2) = 0이 되어, 문장을 구별하는 데 쓸모없는 단어로 처리된다.

### BoW와 TF-IDF의 한계

BoW와 TF-IDF는 간단하고 빠르지만, 단어마다 독립된 칸을 쓰기 때문에 단어 사이의 의미 관계를 담지 못한다. 예를 들어 "고양이"와 "강아지"가 비슷한 단어라는 것을 알 수 없다. 또한 어휘 수만큼 벡터가 길고 대부분이 0인 희소 벡터이며, 단어의 순서 정보도 잃는다. 그래서 단어 자체에 의미를 담는 분산 표현이 필요하다.

참고로 다음 장의 word2vec 모델 중 하나인 CBOW(Continuous Bag-of-Words)의 이름도 여기서 왔다. 주변 단어들의 순서를 무시하고 한꺼번에 본다는 의미다. 또한 TF-IDF를 발전시킨 BM25는 지금도 검색(RAG의 키워드 검색 등)에서 널리 쓰인다.
