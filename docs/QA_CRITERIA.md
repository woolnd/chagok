# QA_CRITERIA — 실험 판정 기준

> 사람만 수정한다. Claude는 hook으로 수정이 막혀 있다.
> QA 에이전트는 판정만 한다. 코드나 문서를 고치지 않는다.

하나라도 실패면 **불합격**. 판정마다 항목별 통과/실패와 근거(명령 출력, diff, 수치)를 남긴다.

| # | 항목 | 통과 조건 | 확인 방법 |
| --- | --- | --- | --- |
| 1 | 평가셋 변경 여부 | `eval/`에 변경 없음 | `git diff --stat main -- eval/` 결과가 비어 있음 |
| 2 | 한 번에 하나만 변경 | 비교 대상 모듈 1개만 켜고 끔. 나머지 설정은 베이스라인과 같음 | 실험 설정 diff 확인 |
| 3 | 속도 제약 | `docs/DESIGN.md`의 속도 목표를 넘지 않음 | 실험 결과의 속도 수치 |
| 4 | 개선폭 | 품질 지표가 베이스라인 대비 5%p 이상 개선. 미만이면 "개선 없음"으로 판정 | 실험 결과 수치, 질문 유형별 수치 |
| 5 | 기록 여부 | `docs/DECISIONS.md`에 문제 / 선택지 / 결과(품질·속도·비용) / 결정이 기록됨, `exp:` 커밋 존재 | 파일과 `git log` 확인 |

- 개선폭 미달(4번 실패)은 실험 실패가 아니라 "채택하지 않음"이다. 기록(5번)은 그래도 해야 한다.
- 채택 여부는 사람이 결정한다. QA는 판정 결과만 보고한다.
