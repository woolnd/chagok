## 2. 평가자 기준표

생성자와 평가자에게 같이 준다. 항목별 통과 / 미달 / 판단 불가. 하나라도 미달이면 탈락, 판단 불가는 사람에게.

| 항목 | 통과 조건 | 미달 예시 |
| --- | --- | --- |
| 답-인용 일치 | 답의 모든 내용이 인용문에 있다 | 인용문에 없는 이유가 답에 있다 |
| 명확함 | 두 가지까지 묻고, 각 답이 하나로 정해진다 | "~에 대해 설명하라", "A는 무엇이고, B는 왜 그런가, C는 무엇으로 해결했나?" (세 가지 이상) |
| 난이도 | 이유·비교·관계를 묻는다 | "편향이란 무엇인가?" |
| 꼬리질문 전제 | 깔고 있는 사실이 노트와 맞다 | 노트와 다른 사실을 전제로 묻는다 |

## 3. 채택 규칙

1. 기준은 실험 전에 정해 이슈 댓글로 남긴다.
2. 한 번에 하나만 바꾼다.
3. 질문별로 맞음/틀림이 어떻게 바뀌었는지 보고, 새로 틀린 질문이 생기면 먼저 열어 본다.
4. 3문항 미만 차이는 잡음으로 보고, 그보다 낮게 정하면 한계를 기록한다.
5. 프롬프트·모델을 바꾸면 다시 재고, 나빠지면 되돌린다.
6. 품질·속도·비용을 모두 기록한다.

## 4. 평가셋

- 회귀(70): 지금 맞히는 질문, Hit@5. PR마다 CI.
- 능력(30): 못 맞힌 질문 + 답없음, MRR. 답없음은 "결과 없음"이면 정답.
- 생성 판정 기록: 문제마다 사람 판정과 평가자 판정.
- 점수를 낸 뒤에는 정답을 바꾸지 않는다. 고칠 때는 memo에 날짜와 이유를 남긴다.
