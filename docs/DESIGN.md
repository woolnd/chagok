## 제약

- 서버에는 벡터DB와 임베딩 모델을 두지 않는다.
- 노트 파일은 수정하지 않는다. `topic`, `keywords`는 따로 저장한다.
- 노트에 근거가 없으면 출제하지 않는다 ("기록 비어 있음").
- 노트는 태그로 감싸 자료로만 다룬다. 출력은 정해진 구조로만 받는다.
- 5%p 미만 차이는 개선으로 보지 않는다.
- 실험은 노트 50개 이상 쌓인 뒤에 한다.

## 문제 품질 기준

| 항목 | 통과 | 탈락 |
| --- | --- | --- |
| 근거 | 노트 내용으로만 물어봄 | 노트에 없는 내용 섞임 |
| 명확함 | 무엇을 설명할지 분명함 | 범위가 넓거나 애매함 |
| 난이도 | 떠올리려면 생각이 필요함 | 단어 뜻만 묻는 수준 |
| 핵심 포인트 | 4~5개, 노트 근거, 중복 없음 | 노트 밖이거나 중복 |

| 점수 | 의미 | 처리 |
| --- | --- | --- |

| 4 | 사소한 수정 | 사람 검토 |

## 운영 수치

- 주말 검토: 주 15개, 5분 이내. 단축키로 승인/거절/수정.
- 거절 사유: 너무 쉬움 / 기록에 없음 / 애매함 / 중복.
- 평일 하루 1개 발송, 주말 미발송. 메일 끝에 누적 발송 수 문구 (예: "오늘로 37번째 복습, 머릿속에 차곡차곡.").
- 주당 8~10개 생성 (초기 15개). 승인 후 2~3주 보관 뒤 발송.
- 남은 발송분 10개 미만이면 알림.

## 실험 지표

| 모듈 | 품질 | 속도 | 비용 |
| --- | --- | --- | --- |
| 하이브리드 검색 + RRF | Recall@5, MRR | 검색 시간 | — |
| BM25에 kiwi | Recall@5 | 색인·검색 시간 | — |
| 리랭커 선택적 사용 | Recall@5 | 검색 시간 | — |
| 메타데이터 먼저 거르기 | Recall@5 | 검색 시간 | — |
| 작게 찾고 크게 넣기 | 승인율 | — | 문제당 토큰 |
| 컨텍스트 압축 | 승인율 | 생성 시간 | 문제당 토큰 |
| 승인 문제 예시 | 승인율 | — | 문제당 토큰 |
| 애매한 것만 사람 검토 | 승인 품질 | 검토 시간 | — |
| 인젝션 대응 | 공격 성공률 | — | 문제당 토큰 |

- 베이스라인: 노트 하나를 통째로 주고 문제 생성 vs 차곡 파이프라인 (승인율, 중복률, 문제당 토큰).
- 생성 모델 선택: 큰 모델 / 작은 모델 / 작은 모델 + 예시를 문제당 비용·승인율·생성 시간으로 비교. 월 예산 안에서 승인율 최고를 선택.
- 인젝션 테스트: 지시문이 섞인 노트 10~20개로 대응 전후 공격 성공률 측정.
- 검색 비교: BM25 / 임베딩 / 하이브리드 / 하이브리드 + 리랭커.

## 평가셋

- 사람이 검수한 150~200개.
- 유형: 여러 노트에 걸친 질문 / 노트에 없는 표현 / 날짜 조건 / 비슷한 개념 구분.
- 결과는 유형별로 나눠 본다.
