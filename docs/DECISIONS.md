## 2026-10-21 실험 시작 기준을 노트 50개에서 10개로 변경 (#14)

**문제**: 노트를 하루 하나씩 직접 정리하다 보니 앞으로 많아야 20개 정도라, 50개를 기다리면 Phase 2 실험을 시작할 수 없다.

**선택지**:
1. 50개 유지
2. 10개에서 1차(잠정) 실험, 20개에서 확정
3. 10개에서 실험하고, 판단이 어려우면 평가셋 질문을 늘린다

**결과**: 노트 10개면 질문 약 60개, 메인(키워드) 약 20개다. 채택 기준 "새로 맞힘 − 새로 틀림 ≥ 3"은 메인 20개에서 15%p 차이라 작은 개선은 놓칠 수 있다.

**결정**: 3번. 노트 10개 이상 쌓이면 실험한다. 메인 질문이 적어 판단이 어려우면 평가셋 질문(키워드 등)을 늘린다. 기능 구현은 노트 개수와 상관없이 한다.

**버린 이유**:
- 1번: 노트 50개는 현실적으로 쌓기 어렵다.
- 2번: 같은 실험을 두 번 돌리는 것보다, 질문을 늘려 한 번에 판단하는 쪽이 단순하다.

## 2026-10-15 데이터와 메일 형식 방향 전환 (#9)

**문제**: AI로 정리한 강사 자료 노트가 내 것 같지 않고, `> 메모:` 245개 중 121개가 자료 오타 지적이라 출제 우선순위 신호로 쓸 수 없었다. 강사 자료는 공개 저장소에 올리기도 어렵다.

**선택지**:
1. 기존 노트 유지 + 내 노트 추가
2. 기존 노트 제외, 직접 정리한 노트(손필기 사진 + Notion)만 사용

**결과** (퍼셉트론 노트 1개 시범):
- 손필기 3장 + Notion 정리 → 노트 1개, 형식 검사 통과, 청크 13개
- 기존 노트 20개와 함께 색인했을 때 "가중치는 왜 손실을 줄이는 방향으로 바꿔?"에 새 노트 섹션이 1등
- 같은 개념이 두 노트에 있으면 상위 5개를 나눠 가짐 → 평가셋 정답은 목록으로 저장해야 함
- AND 게이트 질문에 OR 게이트가 1등 (표·문장이 비슷한 청크) → BM25 비교 후보

**결정**: 2번. 기존 노트 20개와 평가셋 12개는 프로젝트 밖에 보관하고, 오늘부터 직접 정리한 노트를 쌓는다. 함께 정한 것:
- 메일: 질문 1개 + 답(노트 근거) / 꼬리질문 1개(답 없음, 스스로 생각해 보기). 꼬리질문은 노트 안에서 먼저 연결하고 없으면 웹 검색, `[노트 밖]` 표시와 출처 링크
- 노트 합치는 규칙: 손필기가 뼈대, Notion 정의는 섹션 첫 줄, 고쳐 쓰지 않음, 그림은 글로
- 사진 변환 원본은 고치기 전에 따로 저장 (변환 품질 비교, VLM 학습 데이터)
- KV cache·Prefill은 Phase 3에서 프롬프트 캐싱으로 반드시 측정 (비용, 첫 글자까지 시간, 캐시 적중 토큰)
- 다룰 키워드에서 Function Calling 멀티턴 파인튜닝은 제외
- Phase 3 첫 작업: Claude 호출 로그(토큰 수, 캐시 토큰, 첫 글자까지 시간)를 남기는 코드
- 이후 실험 후보: 꼬리질문 노트만 vs 노트+웹 검색, 사진 변환 모델 비교(고친 글자 수·비용·속도), 꼬리질문 중 `[노트 밖]` 비율이 노트가 쌓이며 줄어드는지
- 노트 입력 화면(Streamlit)은 손으로 몇 주 해 본 뒤 만든다

**버린 이유**:
- 1번: 노트가 섞여 있으면 출제 우선순위와 공개 범위를 계속 구분해야 하고, 직접 쓴 노트의 장점(내 질문, 직접 확인한 내용)이 묻힌다. 대가로 노트 50개까지 실험이 늦어지는 것은 감수한다.
